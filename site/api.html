Play your way.

The same game works with touch, keyboard, browser automation, and a small JavaScript interface. No account or API key is needed.

URL options

Try a seeded game. URL games use separate local save slots; reopening a link resumes its progress. Add save=0 for an isolated run with no local-storage writes. Supply a seed when repeatability is needed.

ParameterValues
seed1–128 characters; URL-encode spaces and symbols. Omit for fresh randomness on each move; provide a seed for deterministic play.
timer0 (default) for untimed play; 1–3600 seconds for a timed round. The timer starts when the round opens.
modeclassic (default), insane, or 2048
sizeSquare board, 2–8; default 4
rows, cols2–8 each; override size
movesUp to 1,000 U/D/L/R letters, applied in order
boardComma-separated row-major tile values; 0 is empty
scoreNonnegative integer; requires board
controls, bits0 to hide, 1 to show. Direction buttons are hidden by default.
displayboth (numbers + bit blocks), bits (blocks only), numbers. Overrides bits.
sound0 to mute, 1 for sound effects (default). Browser audio requires a user gesture.
volume0–1; default 0.35
themesystem, light, dark
motion0 to reduce animation
save0 to disable saving and session restoration
#state=…, #round=…Game snapshot or complete timed round. A round link retains its original deadline regardless of timer query options

Saved-game links include the board, score, move count, and generation mode. Seeded links also include the seed and deterministic random state. Random links restore the position but generate fresh future tiles. They do not include undo history. Links work on either hosted copy after replacing the origin and keeping the path, query, and fragment. Up to eight recent sessions and 100 undo steps per session are retained. Best scores are separate for each mode and board size.

JavaScript interface

Wait until window.game2047 exists. Methods are synchronous. Invalid input throws without changing the game.

const game = window.game2047;
game.getState();
game.move("left"); // { changed, gain, state }
game.undo();       // { changed, state }
game.redo();
game.newGame(); // fresh random play; may return needsConfirmation
game.newGame({ seed: "hello", mode: "classic", rows: 4, columns: 4 });
game.newGame({ seed: "test", timeLimit: 120, confirm: true });
game.getState().assessment.result; // null until the round ends
game.shareURL();
game.shareURL({ challenge: true }); // seeded games only

State includes grid in row-major order, rows, columns, score, moves, version (2), randomness (random or seeded), seed, rng (null in random games; a 64-character hexadecimal string in seeded games), legalMoves, gameOver, won, canUndo, and canRedo. Get-state returns a copy. New-game replaces the active session. If the current score is nonzero, it opens a confirmation dialog and returns {needsConfirmation: true, state} without resetting anything. Pass confirm: true to explicitly confirm replacement, or use the confirmation dialog. Invalid configurations still throw before changing the game. A move that changes nothing does not spawn a tile or advance randomness. Moving is blocked while a dialog is open.

Timed rounds

Use the timer beside the title or newGame({timeLimit: 120}). Omit timeLimit or use 0 for untimed play. Timed rounds start immediately; opening menus, leaving the tab, and reloading do not pause or reset the deadline. Undo and redo are allowed while time remains, and never rewind the clock.

getState().assessment includes status (off, running, finished), durationSeconds, remainingMs, startedAt, deadline, and result. At expiry, inputLocked and gameOver are true, gameOverReason is timeout, and legalMoves is empty. Move, undo, and redo return {changed: false, reason: "timeout", state}.

The result records the round’s peak maxTile, final score, scoreGain, moves, movesMade, undos, redos, duration, ending timestamp, mode, board size, randomness, and seed. The maximum tile is retained through undo. Use the same mode, board size, seed, and time limit to compare players. Add save=0 for independent runs.

Timed share links retain the original deadline and completed result. A finished link stays finished; a seed challenge link starts a new timed round. The game2047:timer event carries countdown updates about once per second, while game2047:change reports expiry. Calling getState() always checks the deadline.

Every mode celebrates its first tile of 2047 or greater with noninteractive confetti. The game2047:milestone event reports the achievement once per round, including during reduced-motion play. Repeated undo/redo does not repeat the effect.

Random and seeded play

Random games draw fresh browser randomness for each tile spawn; no future random sequence is stored or shared. Undo restores an earlier board and redo restores the recorded move. Making another move after undo draws fresh randomness.

Seeded games derive spawns from the seed, previous random state, full board, direction, score, and move count. The same version, seed, and moves reproduce a game. A shared seed is still simulatable; deterministic play is not an anti-cheat boundary.

Version 1 saves used seeds for every game. Their boards, scores, and history are retained and upgraded to version 2 seeded continuation. New seed challenges use the revised generation rules.

Browser tools & accessible controls

In browsers with WebMCP, the page registers game2047_get_state, game2047_move, game2047_new_game, game2047_undo, and game2047_redo. Move accepts {"direction":"left"}; new-game accepts the configuration shown above, including timeLimit and explicit confirm. Other tools accept {}. Tools return JSON inside a text content block. Invalid requests return isError: true.

Without WebMCP, enable Direction buttons in Settings (or use controls=1), then use buttons named “Move up”, “Move right”, “Move down”, and “Move left”, or keyboard controls. Each grid cell has data-row, data-column (zero-based), and data-value. ARIA row and column indices are one-based. Disabled direction buttons indicate unavailable moves.

The current snapshot is also available in script#game-state. The game2047:change window event carries the updated snapshot in event.detail. All interfaces use the same rules and local session.
