Play your way.

The same game works with touch, keyboard, browser automation, and a small JavaScript interface. No account or API key is needed.

URL options

Try a seeded game. URL games use separate local save slots; reopening a link resumes its progress. Add save=0 for an isolated, repeatable run with no local-storage writes.

ParameterValues
seed1–128 characters; URL-encode spaces and symbols. Defaults to 2047 when another game parameter is supplied.
modeclassic (default), insane, or 2048
sizeSquare board, 2–8; default 4
rows, cols2–8 each; override size
movesUp to 1,000 U/D/L/R letters, applied in order
boardComma-separated row-major tile values; 0 is empty
scoreNonnegative integer; requires board
controls, bits0 to hide, 1 to show. Direction buttons are hidden by default.
displayboth (numbers + bit blocks), bits (blocks only), numbers. Overrides bits.
sound0 to mute, 1 for sound effects (default). Browser audio requires a user gesture.
volume0–1; default 0.35
themesystem, light, dark
motion0 to reduce animation
save0 to disable saving and session restoration
#state=…Exact game snapshot produced by Share; takes priority over game query parameters

Saved-game links include the board, seed, score, move count, and random state. They do not include undo history. Links work on either hosted copy after replacing the origin and keeping the path, query, and fragment. Up to eight recent sessions and 100 undo steps per session are retained. Best scores are separate for each mode and board size.

JavaScript interface

Wait until window.game2047 exists. Methods are synchronous. Invalid input throws without changing the game.

const game = window.game2047;
game.getState();
game.move("left"); // { changed, gain, state }
game.undo();       // { changed, state }
game.redo();
game.newGame({ seed: "hello", mode: "classic", rows: 4, columns: 4 });
game.shareURL();
game.shareURL({ challenge: true });

State includes grid in row-major order, rows, columns, score, moves, rng as a decimal string, legalMoves, gameOver, won, canUndo, and canRedo. Get-state returns a copy. New-game replaces the active session. A move that changes nothing does not spawn a tile or advance randomness. Moving is blocked while a dialog is open.

Browser tools & accessible controls

In browsers with WebMCP, the page registers game2047_get_state, game2047_move, game2047_new_game, game2047_undo, and game2047_redo. Move accepts {"direction":"left"}; new-game accepts the configuration shown above. Other tools accept {}. Tools return JSON inside a text content block. Invalid requests return isError: true.

Without WebMCP, enable Direction buttons in Settings (or use controls=1), then use buttons named “Move up”, “Move right”, “Move down”, and “Move left”, or keyboard controls. Each grid cell has data-row, data-column (zero-based), and data-value. ARIA row and column indices are one-based. Disabled direction buttons indicate unavailable moves.

The current snapshot is also available in script#game-state. The game2047:change window event carries the updated snapshot in event.detail. All interfaces use the same rules and local session.
